# C2.4 + C4.2 — R3 wave R2.3b note

## What now exists

**gpu.TorchFor (new `core/internal/gpu/torch.go`)**
Single source of truth for torch install specs. Matches `installer_scripts/js/initializeApp.js`:
- NVIDIA: `torch==2.11.0+cu128 torchvision torchaudio==2.11.0+cu128 xformers==0.0.35` / cu128 index
- AMD: `torch==2.11.0 torchvision torchaudio==2.11.0 xformers` / rocm7.2 index
- Apple: `torch==2.11.0 torchvision torchaudio==2.11.0` / default PyPI
- Intel: `torch==2.11.0 torchvision torchaudio==2.11.0` / test/xpu index
- CPU: `torch==2.11.0+cpu torchvision torchaudio==2.11.0` / cpu index
- Custom: `ErrCustomManaged` (caller skips torch install)
- Unknown: error

**env.installTorch**: now uses `gpu.TorchFor`; removed unpinned torch and `intel-extension-for-pytorch`.

**venv.installTorch**: now uses `gpu.TorchFor`; the old `default:` (silent PyPI) is replaced by proper case handling; xformers installed conditionally (NVIDIA/AMD only).

**supervisor.readGPULabel**: `.gpu` file exists + invalid label → returns error, no fallback to `gpu.Detect`.

**cmd_env, cmd_app, cmd_engine**: `--gpu` flag validated through `gpu.Parse` before use.

## Decisions made
- None (existing table in initializeApp.js was authoritative).

## Deviations from plan
- AMD xformers: Go installs it in a separate `uv pip install` call (not combined with torch). Functionally equivalent; no `-U` flag needed for fresh venvs.
- `TorchIndexURL` kept as deprecated shim for external callers.

## Known issues / open items
- None for C2.4/C4.2 specifically. C4.3 still needs: install requirements.txt, read .gpu on startup, run M2 smoke.

## What C4.3 needs to know
- `gpu.TorchFor` is the canonical torch table; C4.3 should use it for uv-mode installs.
- `gpu.ErrCustomManaged` means skip torch (not an error).
- The main venv is at `root.Venvs()/main`.
