# C5.5 — Legacy Gradio host as engine (--proxy=core)

## What now exists

**`core/internal/engine/legacy/`**:
- `LegacyGradioManifest(root)` — built-in manifest for `server.py --no-react` as a `python-venv` engine (health at `/`, 60 s timeout, always-on keep_alive=0).
- `LoadNativeExtensions(dir)` — loads `extensions.json` via `manifest.Load()` and filters to `kind==python-venv` entries (i.e. `proxy:native` extensions from P4).

**`--proxy=python|core` flag** on `tts-webui launch`:
- `--proxy=python` (default): original behaviour unchanged.
- `--proxy=core`: calls `startCoreProxy()` which:
  1. Creates a `lifecycle.Manager`.
  2. Registers and starts `legacy-gradio` engine (server.py).
  3. Loads and starts all `proxy:native` extension engines.
  4. Creates a `router.Router` with `"/"` → Gradio server URL.
  5. Mounts the router on the HTTP server.

## Known issues
- Extension API path prefix for routing (used for URL-based routing per extension) is not yet in the manifest schema. Extensions are registered but all route to their own port; the router routes "/" → Gradio which then proxies extension iframes. Full URL-based routing per extension is a follow-up.
- `TTS_WEBUI_CORE_URL` env var should be injected into the `server.py` process environment so P3 Python code can find it. Currently the env var must be set externally.
