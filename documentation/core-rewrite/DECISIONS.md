# Decisions

Settled decisions for the core rewrite. Add new ones at the bottom with a date; do not rewrite old ones,
supersede them.

| Id | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-10-28 | The core is written in **Go**, pure Go, `CGO_ENABLED=0`. | The core is I/O and process supervision; nothing needs to be linked in. Go gives trivial cross-compiles, `context` cancellation, good `os/exec` and reverse-proxy support, and the maintainer can review it. Rust's advantages (in-process ML, Tauri) are not used by this design. A Tauri shell could still run the Go core as a sidecar later. |
| D2 | 2026-10-28 | **All inference is out-of-process.** Engines are Python venvs, native binaries (audio.cpp, whisper.cpp, llama-server) or remote APIs. | Crash isolation (CUDA OOM, ggml segfaults), no GPU build matrix in the core, engines update independently. Cost: about 300–500 MB VRAM CUDA context per engine process, handled by idle stop and a resident cap. |
| D3 | 2026-10-28 | One venv per engine, **no shared torch at runtime**; disk is shared through **uv hardlinks** from a cache on the same volume. | Keeps projects from breaking each other while saving most of the disk. Shared torch in one process would share the crash domain and dependencies for little gain. |
| D4 | 2026-10-28 | **Side-by-side rewrite.** Legacy stays runnable; each area is first re-driven by Go in legacy-compat mode, then replaced natively behind a flag, then the default flips at a milestone. | Lets old and new be tested against each other at every checkpoint. |
| D5 | 2026-10-28 | Engines are described by an **engine manifest** extending `extensions.json` entries (`kind`, install, `launch`, `health`, `api`, `ui`, `cancel`, `keep_alive`). | One supervisor and router for every engine kind; audio.cpp is just another entry. |
| D6 | 2026-10-28 | The UI becomes a **Vite SPA embedded in the binary** (`go:embed`). Node exists only in development and CI. | Removes the Next.js server and Node from user installs; UI and core ship together, so they cannot skew. |
| D7 | 2026-10-29 | **tts-webui-ignition UI is kept** in `core/ui/` (only the Go-embedded page; the Neutralino shell and old screens are not carried over); its logic is moved into Go. | Ignition is the modern launcher UX; its logic is thin shell calls that map cleanly to Go step endpoints. |
| D8 | 2026-10-29 | Go module path `github.com/rsxdalv/TTS-WebUI/core` (matches the remote's capitalisation). Go 1.27. | Set in C0. |
| D9 | 2026-10-29 | The core's HTTP server binds to 127.0.0.1, requires a per-run token on `/api/*`, and checks `Host` and `Origin`. No generic "run a shell string" endpoint, ever. | The server starts processes; any web page could otherwise reach it via localhost or DNS rebinding. |
| D-open-1 | 2026-10-29 | **Core public port: 7700** (fixed default, overridable by `--port`). | No collision with any legacy port (3000, 7767, 7769, 7770, 7771, 7778, 27771+). provisional (director) |
| D-open-2 | 2026-10-29 | **Engine manifest schema**: accept the C5.1 draft schema when the checkpoint produces one; reviewed before merge into `core/rewrite`. | Most reversible; defer schema lock until the draft exists. provisional (director) |
| D-open-3 | 2026-10-29 | **App distribution after git pull**: pinned `tts-webui` package installed by uv into the main env. | Decouples app releases from git history, enables reproducible installs. provisional (director) |
| D-open-4 | 2026-10-29 | **Launcher UI placement**: merge into the `ui/` Vite SPA as the `/setup` route during C6.2. | Single embed, one dev server, shared design system. provisional (director) |
| D-open-5 | 2026-10-29 | **Update signing**: minisign. Throwaway test key checked into `core/internal/selfupdate/testdata/` for CI; real key custody stays with the human. Never generate or store a release signing key in CI or the repo. | Lightweight, reproducible, fits the Go stdlib. provisional (director) |
| D-open-6 | 2026-10-29 | **Python version for new installs**: keep 3.10.11 until P4 is done, then per-engine. | Safe conservative default; avoids breaking existing extension venvs. provisional (director) |
| D10 | 2026-10-29 | **Supersedes D-open-4 for now.** M1 ships the `launcher/` Vite build embedded in the binary, using a `core` platform adapter. Merging the launcher into `ui/` as `/setup` waits until C6 is real. | Fastest route to a usable Go launcher; `ui/` is still a scaffold. |
| D11 | 2026-10-29 | **Verification rules** (PLAN.md): `done` needs a recorded end-to-end smoke against the real binary; `built` is the status for unit-tested but unexercised work; research must cite what it read. | Run 1 marked placeholder and guessed work as done. |
| D12 | 2026-10-29 | **The launcher seam is the step, not the OS.** The core launcher is the page in `core/ui` whose components call only the typed step and app endpoints. Go does all the work and owns all state checks. No browser-side `exec`/`stat`/`readFile` equivalent, and no Go endpoint that runs a command or reads a path given by the client. Amends D7 and D10 ("platform adapter"). | Run 2 re-implemented Neutralino's OS calls in the browser as stubs; that layer cannot work there and invites a shell endpoint. The Go steps already exist; sharing only visual components keeps the shipped Neutralino launcher untouched. |
| D13 | 2026-11-03 | **The rewrite proceeds in rings:** launcher → supervisor → uv env → `server.py` → core extensions → native engines → React UI very late. Each must work for real, and the human signs it off, before the next starts. Other code is parked. Replaces waves and milestones M1–M4 as the unit of work. | Breadth-first waves built many packages nothing exercised, and most of the budget went on rework. Each ring runs on the last, so a hollow one fails fast. |
| D14 | 2026-11-03 | **Runs are semi-supervised:** one coordinator with a few long-lived workers, stopping at plan, design and demo gates through `#askQuestions`. Only the human marks a ring `done`. Replaces the unattended director. | Unattended runs reported hollow or wrong work as finished and only surfaced it after a whole run. |
| D15 | 2026-11-03 | **uv comes before `server.py`.** The old server runs unchanged inside a uv venv as its own ring. uv is a CLI owned by the core (pin, main venv, engine venvs); `server.py` also calls it for extensions; the launcher UI never touches it. One version and one cache across both. | `server.py` needs an env to run from; converting it on conda would mean verifying it twice. Provisional: confirm at ring 3's plan gate. |
| D16 | 2026-11-19 | **For the Go installer-scripts and react-ui backend port only**, the shared brief (`tts-comms/BRIEF.md`) supersedes D13's ring order and D14's stop-at-gates rule. Sessions run unattended and the human reviews once at the end. Nothing is cut over: every Go path stays behind a switch that is off by default, and nothing merges into `main`. | The user's decision on 2026-11-19. |
| D17 | 2026-11-19 | **D9 applies to port 3000 without the token.** When the Go proxy is on, port 3000 binds loopback only and checks `Host` and `Origin` as D9 requires. It has no per-run token, and it exposes no launcher endpoint and starts no processes. Port 7700 keeps D9 in full. Details are in `CONTRACTS.md` section 6. | Next serves the pages on 3000, so they cannot receive the launcher's token. The token protects the endpoints that start processes, and those stay on 7700. Provisional: LAN access is lost while the proxy is on, so this must be confirmed before the proxy becomes the default. |
| D19 | 2026-11-19 | **The Go installer steps are the default.** With `TTS_GO_STEPS` unset or empty, the mamba, install, update and diagnostic steps run their Go ports (`core/installer_scripts`). `TTS_GO_STEPS=none` runs the original scripts for every step; a comma list runs only the named ports; unknown names stay an error. Each step logs a `[launcher]` line saying which path ran. Supersedes the steps part of D16 ("off by default"). The proxy and route defaults are D18, not this decision. | The user decided on 2026-11-19 to cut over on `core/go-port`. The ports were compared with the scripts on Windows (I1-I5) and run on Linux in WSL (C1); the scripts stay as the escape hatch. |
| D20 | 2026-11-19 | **Supersedes the provisional part of D17: D17 is final, with an opt-in LAN mode.** By default the Go proxy on port 3000 binds loopback only and keeps D17's Host and Origin rules. `TTS_GO_PROXY_LISTEN=lan` makes it listen on every interface and also accept this machine's interface addresses and the hosts in `TTS_GO_PROXY_ALLOWED_HOSTS`. Every other host and origin is still refused. Next and Gradio stay on loopback, and the launcher logs a warning that the UI is reachable without a password. Details: `CONTRACTS.md` sections 4 and 6. | The user's decision on 2026-11-19: users who open the UI from another device keep that option, and no deployment is exposed by default. |
| D18 | 2026-11-19 | **Cutover of the UI on `core/go-port`: the Go proxy and every route claim are on by default, and the UI is a static export served by Go.** With no environment set, Go owns port 3000 (loopback only, LAN opt-in per D20) and serves `react-ui/out` with no Next process, and `react-ui/public` live. An install with only the old server build gets `next start` behind the proxy, with one log line. An install with neither gets a clear error. `TTS_GO_PROXY=0` brings back Next on port 3000 as before, building the server build first when it is missing. `TTS_GO_ROUTES=none` turns the claims off. Supersedes BRIEF.md's "nothing is cut over by default" for the UI and proxy. Details: `CONTRACTS.md` sections 4 and 10. | The user's decision on 2026-11-19 to cut over on `core/go-port` (`tts-comms/CUTOVER.md`). No Node at runtime in the default mode, and uploads are served at once (R1's O2). Amended by S2F: when Next serves the UI, a server build older than the export is rebuilt once first, and a failed rebuild starts nothing. |
