# P3 — `setup_proxy_extension` delegates to core

**Status**: done
**Branch**: core/wave-4
**Commit**: 591da02

## What now exists
- `tts_webui/extensions_loader/setup_proxy_extension.py` — modified.

## Behaviour
- If `TTS_WEBUI_CORE_URL` is **not** set: original local-subprocess behaviour unchanged (`_setup_proxy_extension_local`).
- If `TTS_WEBUI_CORE_URL` **is** set: `_setup_proxy_extension_via_core` is called instead:
  - `run_extension`: POSTs `$TTS_WEBUI_CORE_URL/api/engines/{package_name}/start` with `X-TTS-Token` header.
  - Reads `{"running": true, "port": N}` response, constructs proxy URL, registers route.
  - `shutdown_extension`: POSTs `.../stop`.
  - Falls back to same Gradio iframe UI pattern.

## Auth
- Token read from `TTS_WEBUI_TOKEN` env var, sent as `X-TTS-Token`.
- Uses stdlib `urllib.request` only — no new Python dependencies.

## Test
- Original path: unchanged; existing app tests cover it.
- Core-delegate path: `needs human verification` — requires a running Go core.

## For C5.5
- C5.5 will register legacy Gradio engines in the lifecycle manager so P3's
  POST /api/engines/{id}/start actually starts them via the Go core.
