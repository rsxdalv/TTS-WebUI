# C5.2 — Python-venv engine install

## What now exists

- **Package:** `core/internal/engine/venv`
  - `Install(ctx, root, m, gpuLabel)` — creates versioned venv at `.venvs/<name>@0`, installs torch (variant from GPU label), torchcodec, xformers==0.0.35, compat pins (gradio, ffmpeg-python, matplotlib), then engine requirements. Idempotent: skips when pointer file and versioned dir both present.
  - `Current(root, name) (string, error)` — reads `.venvs/<name>.current` pointer file.
  - `VenvPath(root, name, version) string` — resolves the versioned venv directory path.
  - `sanitizeName` converts `.` and `/` to `_` in package names.
  - Torch versions mirror `get_torch_command.py` (2.11.0, cu128 for NVIDIA, rocm7.2 for AMD).

- **Command:** `tts-webui engine install <id> [--root <dir>]`
  - Detects GPU, loads manifests, calls `venv.Install`. Falls back to CPU on GPU detection error.

## Decisions made

- Version field fixed at `"0"` until the manifest schema adds `extension_platform_version` (already in extensions.json but not in the Go struct). A follow-up can add it to `Manifest` and use it here.

## Deviations

- The `xformers==0.0.35` step may fail on non-NVIDIA platforms; this mirrors the Python behavior (best-effort). Not treated as fatal; marked as known issue.

## Known issues

- `xformers` may fail to install on CPU/Apple/AMD. Callers can ignore these non-fatal errors; full error propagation is retained so the issue is visible.

## What C5.5 needs to know

- `venv.Install(ctx, root, m, gpuLabel)` is ready. C5.5 can call it from the engine lifecycle when starting a `proxy: native` engine for the first time.
- The venv path for engine `pkg` is `.venvs/<sanitized_pkg>@0`; the python binary is at `<venv>/bin/python` (Unix) or `<venv>/Scripts/python.exe` (Windows).
