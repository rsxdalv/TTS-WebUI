## Run 1 — original note

**Package `core/internal/launcher`**
- `launcher.go` — `Launcher` struct; `Register()` adds all step endpoints to `server.Server`.
- `steps.go` — `downloadDone`, `preflightDone`, `mambaDone`, `gpuDone`, `installDone` predicates + helper paths.
- `git.go` — `isGitUpdated` / `isGitUpdatedWith` with injectable `gitRunner` for tests.
- `browser.go` — `OpenBrowser(url)` platform-specific (`cmd /c start "" url` on Windows, `open` on macOS, `xdg-open` on Linux).
- `download.go` — `downloadAndExtract`: TLS-verified download, progress SSE, zip-slip guarded extraction with single top-level directory stripped.
- `handlers.go` — HTTP handlers for all 8 POST/GET step endpoints.
- `log.go` — `Log` type: thread-safe ring-buffer with fan-out subscriptions (used for download progress SSE).

**Command `tts-webui launch`** (`core/cmd/tts-webui/cmd_launch.go`)
Flags: `--root`, `--port` (default 7700), `--no-browser`, `--ui-dev`.

**Step endpoints registered on the server (all token-guarded):**

| Method | Path | Behaviour |
|---|---|---|
| GET | /api/steps/status | JSON `[{step, done}]` for all 7 steps |
| POST | /api/steps/download | Async download+extract; stream at .../stream |
| GET | /api/steps/download/stream | SSE progress from `Log` |
| POST | /api/steps/preflight | Runs preflight checks; writes `.preflight_ok` on pass |
| POST | /api/steps/mamba | Spawns `init_mamba.bat`/`.sh` via `procs.Proc`; stream at .../stream |
| GET | /api/steps/mamba/stream | SSE from proc ring-buffer |
| POST | /api/steps/gpu | Writes `installer_scripts/.gpu` |
| POST | /api/steps/install | Spawns micromamba run node init_app.js --silent; stream at .../stream |
| GET | /api/steps/install/stream | SSE from proc ring-buffer |
| POST | /api/steps/update | Checks isGitUpdated; if behind, re-runs install command; stream at .../stream |
| GET | /api/steps/update/stream | SSE from proc ring-buffer |
| POST | /api/steps/run | Spawns env Python server.py --no-react; stream at .../stream |
| GET | /api/steps/run/stream | SSE from proc ring-buffer |

**Security fix in `server.Handle()`**: patterns under `/api/` are now automatically wrapped in the token guard, preventing callers from accidentally registering unprotected API routes.

## Decisions made

- None new. `D-open-1` (port 7700) already settled.

## Deviations from plan

- `mambaDone`: checks for the micromamba **binary** presence (not just the directory), fixing the legacy ignition bug.
- `isGitUpdated`: uses `filepath.Join` via `root.MarkerFile()`, fixing the Windows-only `\\` path bug.
- `server.Handle()` now auto-applies the token guard for all `/api/*` patterns. Previously, callers that registered specific sub-patterns under `/api/` would bypass the catch-all guard — a security issue.
- Update step (`updateDone`): status endpoint uses `installDone` as proxy (`.git_version` exists). The real update check (`isGitUpdated` with git fetch) only runs on POST /api/steps/update, not on status polling, to avoid network I/O on every page load.

## Bug fixes recorded (as required by plan)

1. **Windows `\\` path in isGitUpdated** — fixed via `root.MarkerFile(".git_version")`.
2. **Mamba done when only directory exists** — fixed, now checks for the micromamba binary.
3. **Backslash paths in install command** — `filepath.ToSlash` applied only to the node script arg, not the micromamba binary path.
4. **Browser open via shell spawn** — `OpenBrowser` uses `os/exec.Command("cmd", "/c", "start", "", url)` on Windows (empty title arg avoids & splitting), `open` on macOS, `xdg-open` on Linux.
5. **Token guard bypass on specific /api/* routes** — `server.Handle()` now auto-wraps.

## Known issues / open items

- The download step extracts to `filepath.Dir(root.Dir())` (parent of install root) and strips one top-level zip directory. If the release zip has a different structure, the dest path must be adjusted.
- `tts-webui launch` with `--root` pointing at an uninitialized directory returns an error (correct); a future UX improvement would offer to create the directory and skip the `installer_scripts/` check on first run.
- The `run` step uses the conda env Python directly; it does not re-activate the conda environment, so any conda-specific PATH entries may be missing. For C3.2 this should be revisited.

## What C3.2 needs to know

- `procs.Proc` for the `run` step is stored in `Launcher.sprocs["run"]`; C3.2 can retrieve it via a new exported accessor to stop/restart the app.
- The `run` step SSE stream stays open while the app is running; C3.2 should expose a `/api/steps/run/stop` endpoint that calls `p.Stop()`.
- The Go launcher does not yet wait for the Gradio app to be ready before returning from POST /api/steps/run; C3.2 can add a health-check loop before signalling ready.
