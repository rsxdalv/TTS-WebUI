# C2.4 — GPU labels → PyTorchChoice strings (run 2 fix)

**Status**: built  
**Branch**: core/r2-wave-1  
**Commit**: 42633e2

## Reopened gaps addressed (item by item)

1. **Labels changed to exact PyTorchChoice strings** in `core/internal/gpu/gpu.go`:
   - `NVIDIA = "NVIDIA GPU"`, `AMD = "AMD GPU (ROCM, Linux only)"`, `Apple = "Apple M Series Chip"`,
     `Intel = "Intel GPU (XPU)"`, `CPU = "CPU"`, `Custom = "Custom (Manual torch install)"`.
   - Added `allLabels` var for iteration in `Parse()`.

2. **`Parse(s string) (Label, error)` added** — returns error for any string not in `allLabels`.
   An unknown label is never silently accepted (no fallback to CPU torch install).

3. **Tests** in `gpu_test.go`:
   - `TestParse` — table-driven, covers all 6 valid labels, verifies 6 old/unknown strings return error.
   - `TestParseRealGPUFile` — reads `testdata/gpu_real.txt` (content: `NVIDIA GPU`, mirrors real installer_scripts/.gpu) and calls `Parse()` successfully.

4. **`env.go` `TorchIndexURL` switch** updated to `string(gpu.NVIDIA)` etc.; intel package append
   condition updated from the old string literal to `string(gpu.Intel)`. Added `gpu` package import.

5. **`cmd_env.go` and `cmd_app.go` help text** updated to list PyTorchChoice strings.

6. **`venv.go` `installTorch` switch** updated to PyTorchChoice strings.

7. **`launcher/handlers.go` `handleGPU()`** now validates the label with `gpu.Parse()` before writing
   to the `.gpu` marker file. Returns 400 for unknown labels.

8. **All test files** updated: `env_test.go`, `env_integration_test.go`, `venv_test.go`,
   `update_test.go`, `launcher_test.go`. `native_test.go` and `audiocpp_test.go` were intentionally
   NOT changed — their `"cpu"` strings are URL template tokens `{gpu}`, not PyTorchChoice labels.

All changed packages pass: `gpu`, `env`, `launcher`, `engine/venv`, `engine/update`.
