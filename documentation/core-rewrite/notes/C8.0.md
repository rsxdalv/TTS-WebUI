## Server binary and startup
- Executable: `audiocpp_server` (also `audiocpp_cli` for CLI).
- Server starts with a JSON config file:
  `build/bin/audiocpp_server --config server.json`
  Source: README.md ("Server" section, "Start:" command, read 2026-11-02)
- Default port: 8080. Default bind: 127.0.0.1 (localhost).
  Source: Both README.md and app/server/README.md config examples use
  `"host": "127.0.0.1"` and `"port": 8080` as defaults (read 2026-11-02).
  api.md uses `http://127.0.0.1:8080` as the example URL without qualification.
- The `host` and `port` fields are JSON config keys; they are NOT CLI flags.
  CLI flags: `--config`, `--ui`, `--no-ui`, `--ui-management`, `--backend`,
  `--log`, `--log-file`, `--max-loaded-models`, `--idle-unload-ms`,
  `--min-free-memory-mb`, `--cors-origins`, `--parallel-jobs`.
  Source: app/server/README.md (read 2026-11-02; see "Loading and memory" table).
  Claims of `--host` or `--port` CLI flags are not supported by the docs.
  Claims of `--idle-stop-s` or `idle_stop_s` are not supported; the correct key
  is `idle_unload_ms` with CLI flag `--idle-unload-ms`.

## Loading and memory (sourced from app/server/README.md "Loading and memory" table, 2026-11-02)
| Config key | Default | What it controls |
|---|---|---|
| `lazy_load` | false | Defer model loading until first request |
| `max_loaded_models` | 0 | Max resident models; 0=unlimited; CLI `--max-loaded-models <n>` |
| `idle_unload_ms` | 0 | Unload after N ms of no activity; 0=disabled; CLI `--idle-unload-ms <ms>` |
| `min_free_memory_mb` | 0 | Memory headroom before load; 0=disabled |

## API endpoints (sourced from app/server/api.md)
- `GET /health` → `{"status":"ok","backend":"...","models":N,"version":"..."}`
- `GET /v1/models` → OpenAI-style model list with optional `include_params=true`
- `POST /v1/audio/speech` → WAV (offline) or SSE streaming with `speech.audio.delta` events
- `POST /v1/tasks/run` → generic sync request
- `POST /v1/tasks/stream` → generic SSE streaming request
- `POST /v1/tasks/batch` → native batch
- `POST /v1/tasks/unload_models` → unload by id
- `POST /v1/tasks/unload_all_models` → unload all

## Model load/unload (sourced from app/server/api.md + app/server/README.md, 2026-11-02)
- `POST /v1/models/load` EXISTS: confirmed by api.md GET /v1/models section — "false for a model
  loaded later through `POST /v1/models/load`". Models loaded this way have `"configured": false`.
- Unload: `POST /v1/tasks/unload_models` (by model_ids array) and
  `POST /v1/tasks/unload_all_models`. Both sourced from api.md.
- `idle_unload_ms` config key EXISTS (see Loading and memory table above).
  Source: app/server/README.md "Loading and memory" table.
- There is NO `/v1/models/unload` endpoint; unload goes through `/v1/tasks/unload_*`.

## Cancel behaviour (sourced from app/server/api.md)
"An SSE client that disconnects stops the run within the next event or two."
"A JSON client that disconnects leaves its run to finish."
Conclusion: cancel = disconnect on a streaming SSE request. NO explicit cancel endpoint exists.
For C8.2 engine manifest: `cancel: "disconnect"`, and the engine must be configured with `mode: "streaming"`.
Offline mode cannot be cancelled; do not use it if cancel is required.

## Streaming format (sourced from app/server/api.md)
SSE request: `"stream_format": "sse"` in JSON body.
Events:
  - `data: {"type":"speech.audio.delta","audio":"<base64 PCM>"}` (per chunk)
  - `data: {"type":"speech.audio.done","timing":{...}}`
  - `data: [DONE]`
PCM format: set with `"response_format": "pcm"`.
WAV response: default for offline (no stream_format field).
