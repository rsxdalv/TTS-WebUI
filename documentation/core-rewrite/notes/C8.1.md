# C8.1 — Native engine kind

**Status**: done
**Branch**: core/wave-6
**Commit**: f107e41 (initial) + gofmt/fixes squashed into review pass

## What now exists

- `core/internal/engine/native/` — new package
  - `Resolve(ctx, manifest.Manifest, gpuLabel, cacheDir) (string, error)` — resolves asset URL from
    `NativeAsset.URLTemplate` (placeholders: `{version}`, `{os}`, `{arch}`, `{gpu}`, `{ext}`), downloads,
    verifies SHA256 from `NativeAsset.Checksums` map or sidecar `.sha256` URL, extracts zip/tar.gz/tar.xz,
    returns absolute path to the binary. Cache hit (binary already on disk) skips download.
  - `Launch(ctx, *lifecycle.Manager, manifest.Manifest, gpuLabel, cacheDir) error` — calls Resolve, patches
    `Launch.Cmd[0]` with the resolved binary path, registers+starts in lifecycle.Manager.
  - `HTTPClient` var — injectable `*http.Client` for tests.
  - `maxEntryBytes = 4 GiB` — per-entry extraction size limit (both zip and tar streams).
  - `tar_unix.go` / `tar_windows.go` — platform-specific `tarXZCommand(ctx, src, destDir)` using system tar
    (bsdtar on Windows, GNU tar on Unix). Context cancellation forwarded via `exec.CommandContext`.

- `core/internal/engine/manifest/manifest.go` — added `NativeAsset` struct (`URLTemplate`, `Version`,
  `Checksums`, `BinaryPath`) and `NativeAsset *NativeAsset` field on `Engine`.

- `core/cmd/tts-webui/cmd_engine.go` — extended with `engine native install <id> [--gpu <label>]`.
  Detects GPU if `--gpu` omitted, resolves and prints the binary path.

## Known issues / deviations
- tar.xz uses system `tar` subprocess (same pattern as `tools` package). This is not "pure Go" per D1 but
  follows the established precedent from C4.1. A pure-Go xz library (`ulikunitz/xz`) would be a clean fix
  but needs a DECISIONS.md entry. For now the shell-out is only reached when `URLTemplate` hardcodes `.tar.xz`.
- `{ext}` in URLTemplate resolves to `zip` (Windows) or `tar.gz` (others); tar.xz assets must hardcode the
  extension.
- `Launch()` is tested via logic verification; an end-to-end test with a real lifecycle.Manager requires a
  fake HTTP server binary and belongs in an integration test.
