# C6.1 — Core API replacing Next.js API routes

## What now exists

- **Package:** `core/internal/api`
  - `Register(srv, root)` — registers three routes on the server.
  - `GET /api/generations/{collection}/{name...}` — path-traversal-safe file serving from `outputs/`, `favorites/`, `voices/`. Returns 404 for missing, 403 for traversal attempts. Sets Content-Type from extension.
  - `POST /api/upload` — multipart/form-data, field `file`, 50 MB limit. Sanitizes filename (base-name only), writes to `outputs/uploads/`, returns `{"path": "<relative>"}`.
  - `GET /api/version` — returns `{"version": "<version.String()>"}`.

- **TypeScript types:** `ui/src/api/types.ts` — `UploadResponse`, `VersionResponse`.

## Next.js routes NOT ported (documented here)

- `pages/api/gradio/[name].tsx` — not needed; the SPA uses `@gradio/client` directly.
- `pages/api/gradio-file-proxy/[...path].tsx` — covered by the router package (C5.3).

## Decisions made

- All three routes go through the existing token guard in `server.Handle` automatically (they all contain `/api/`).
- Collection mapping is a fixed allow-list: `outputs`, `favorites`, `voices`. Other subdirectories can be added later.

## Deviations

- None from the spec.

## Known issues

- The `outputs/uploads/` directory is created lazily on first upload. No cleanup logic; that is application-layer concern.

## What C6.3 needs to know

- `api.Register(srv, root)` is available. Call it from the serve command's startup after the server is created.
- Types file is at `ui/src/api/types.ts`.
