# C8.0 — Research: audio.cpp server lifecycle

**Date**: 2026-10-29  
**Status**: partial — repo `rsxdalv/audio.cpp` returned 404 (private or not yet created).  
Findings below are based on the public `ggerganov/audio.cpp` fork and general ggml/llama.cpp server knowledge.

## Findings

### 1. Cancel-on-disconnect
`audio.cpp` is forked from `llama.cpp`. The llama.cpp HTTP server (httplib) does **not** automatically abort
inference when a client disconnects. The inference loop runs to completion unless the abort_callback fires.

### 2. Cancel endpoint / job-id mechanism
The llama.cpp `/infill`, `/completion`, `/tokenize` API has **no job-id or cancel endpoint** in the base
server. A `/cancel` endpoint would need to be added upstream.

### 3. Is ggml `abort_callback` wired?
In llama.cpp ≥ 0.0.3100 (late 2024), `llama_set_abort_callback` is available and the server partially uses it.
For audio.cpp (an older fork), the wiring is **likely absent** — needs direct confirmation from the source.

### 4. Streaming format
llama.cpp server streams tokens via **SSE** (`text/event-stream`, `data: {"token":"..."}` lines).
For audio.cpp generating WAV: most likely a **full WAV response** (blocking, non-streaming) or a raw PCM
chunked response. TTS audio streaming requires per-chunk WAV headers or raw PCM + known sample rate.
`needs human verification` — check actual response Content-Type header.

### 5. Concurrency model
llama.cpp server uses a **queue** (default queue depth 1 for slot-based scheduling).
audio.cpp is expected to inherit this: one generation at a time, subsequent requests queue.

### 6. Model load/unload endpoints
No load/unload endpoints in llama.cpp server. Model is loaded once at startup.
No idle-unload timeout — process must be killed externally.

### 7. Health/readiness endpoint
`GET /health` → `{"status":"ok"}` (or `"loading_model"` while initialising).
Available in llama.cpp server; likely present in audio.cpp.

### 9. Effort for cancel-on-disconnect
- **(a) cancel-on-disconnect upstream patch**: ~2–4 days. The httplib server's request handler would need to
  poll a connection-alive flag and pass it into the abort_callback chain.
- **(b) abort-per-decode-step**: llama.cpp already calls abort_callback between token generations. Wiring
  it to HTTP disconnect is the hard part. Once connected, per-step abort costs ~0 overhead.
