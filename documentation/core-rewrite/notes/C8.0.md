## API endpoints (sourced from app/server/api.md)
- `GET /health` → `{"status":"ok","backend":"...","models":N,"version":"..."}`
- `GET /v1/models` → OpenAI-style model list with optional `include_params=true`
- `POST /v1/audio/speech` → WAV (offline) or SSE streaming with `speech.audio.delta` events
- `POST /v1/tasks/run` → generic sync request
- `POST /v1/tasks/stream` → generic SSE streaming request
- `POST /v1/tasks/batch` → native batch
- `POST /v1/tasks/unload_models` → unload by id
- `POST /v1/tasks/unload_all_models` → unload all

## Cancel behaviour (sourced from app/server/api.md)
"An SSE client that disconnects stops the run within the next event or two."
"A JSON client that disconnects leaves its run to finish."
Conclusion: cancel = disconnect on a streaming SSE request. NO explicit cancel endpoint exists.
For C8.2 engine manifest: `cancel: "disconnect"`, and the engine must be configured with `mode: "streaming"`.
Offline mode cannot be cancelled; do not use it if cancel is required.

## Streaming format (sourced from app/server/api.md)
SSE request: `"stream_format": "sse"` in JSON body.
Events:
  - `data: {"type":"speech.audio.delta","audio":"<base64 PCM>"}` (per chunk)
  - `data: {"type":"speech.audio.done","timing":{...}}`
  - `data: [DONE]`
PCM format: set with `"response_format": "pcm"`.
WAV response: default for offline (no stream_format field).

## Implications for C8.1/C8.2
- C8.1 (native engine): Pick Windows `cuda12.4` for NVIDIA (most compatible), `vulkan-portable` for AMD/Vulkan fallback, `cpu` for CPU. Linux: `cuda12.8` for NVIDIA, `cpu` for AMD/CPU.
- C8.2 manifest: `cancel: "disconnect"`. Use streaming mode. Health: `GET /health`. OpenAI speech API: `POST /v1/audio/speech`.

### 6. Model load/unload
Source: https://raw.githubusercontent.com/0xShug0/audio.cpp/main/app/server/api.md

There are no `/v1/models/load` or `/v1/models/unload` endpoints.
Models loaded through the server config are exposed as `"configured": true` entries
in `GET /v1/models`; models loaded later (via `POST /v1/models/load` — this endpoint
exists, confirmed by the sentence "false for a model loaded later through
`POST /v1/models/load`" in the API doc's `/v1/models` section).
Unload: `POST /v1/tasks/unload_models` (by id) and `POST /v1/tasks/unload_all_models`.
No `idle_unload_ms` config option mentioned in the API doc.

### 9. Cancel architecture
Source: https://raw.githubusercontent.com/0xShug0/audio.cpp/main/app/server/api.md

> "An SSE client that disconnects stops the run within the next event or two."
> "A JSON client that disconnects leaves its run to finish."

The cancel mechanism is SSE-disconnect based: the server detects TCP disconnect
and aborts the in-progress generation "within the next event or two". There is no
explicit `/cancel` endpoint. For the engine manifest: `cancel: "disconnect"`.
The engine must be invoked with `"stream_format": "sse"` in the request body;
offline (non-SSE) requests cannot be cancelled by disconnect.
