# C3.2 Run 3 — Supervisor context fix

**Status:** `built` — HEAVY_CHECKS=no; end-to-end smoke on a real install (no-orphan proof) is the heavy check.

## What was fixed

**Root cause (R2.3 "Still open"):** `handleAppStart` passed `r.Context()` to `Supervisor.Start`, which in turn
passed it to `exec.CommandContext`. Go cancels the context when the handler returns, killing the app immediately.

**Fix:** `Supervisor` now owns a process context independent of any HTTP request:
- Added `supCtx context.Context` and `supCancel context.CancelFunc` fields to `Supervisor`.
- `Start(setupCtx)` creates `supCtx, supCancel = context.WithCancel(context.Background())` while holding `mu`,
  uses `setupCtx` only for setup work (tools.EnsureAll, env.CreateMain), and passes `supCtx` to `p.Start()`.
- `Stop()` cancels `supCtx` after calling `proc.Stop()` for a graceful stop.
- `Restart(setupCtx)` calls `Stop` then `Start(setupCtx)` — the new processes get a fresh supervisor context.
- Error path in `Start` cancels and nils out `supCtx`/`supCancel` to leave a clean state.

## Tests

- `TestSupervisorOwnedContext`: Start (which fails with no binary), cancel setupCtx, Stop — no panic or race.
- `TestSupervisorContextCancelledAfterStop`: after Stop on a never-started supervisor, supCtx/supCancel are nil.

## Known issues (heavy check)

- No-orphan proof: requires a real install to verify that all child processes die after `Stop` and after the
  binary exits. Write the smoke as:
  ```
  tts-webui launch --root <scratch> &; sleep 5; POST /api/app/start; sleep 5;
  POST /api/app/stop; pgrep -P $PID || echo "no orphans"
  ```
  Expected: no PIDs survive after `app/stop`.
