# C4.3 — App from uv env (--env=uv)

## What now exists

- **`core/internal/launcher/steps.go`:**
  - `uvPythonPath(root)` — returns `.venvs/main/bin/python` (Unix) or `.venvs/main/Scripts/python.exe` (Windows).

- **`core/internal/launcher/launcher.go`:**
  - `LauncherOptions{EnvMode string}` struct.
  - `NewWithOptions(root, opts)` — creates a Launcher with explicit options.
  - `New(root)` now delegates to `NewWithOptions` with empty options (conda default).

- **`core/internal/launcher/supervisor.go`:**
  - `Supervisor.envMode string` field.
  - `newSupervisor(root, envMode)` signature updated.
  - In `Start(ctx)`, when `envMode == "uv"`:
    1. Calls `tools.EnsureAll(ctx, root)` to guarantee uv/ffmpeg/MinGit.
    2. Calls `gpu.Detect(ctx)`.
    3. Creates main venv via `env.CreateMain` if `.venvs/main` not present.
    4. Uses `uvPythonPath(root)` for the Gradio process.
    5. Builds modified env via `buildUVEnv(root)` — prepends `tools/uv`, `tools/ffmpeg`, and `tools/mingit/cmd` (Windows) to PATH.

- **`core/cmd/tts-webui/cmd_launch.go`:**
  - `--env=conda|uv` flag (default: `conda`). Validated; unknown values return error.
  - Passes mode to `launcher.NewWithOptions`.

## Parity

`needs human verification` (M2: uv mode produces audio on Windows and Linux).

## Known issues

- PATH injection for ffmpeg uses the flat tool directory. If the ffmpeg archive extracts with a nested `bin/` subdir, the injected path may not have the right binaries. Known limitation for follow-up.
- xformers install step in the main uv venv is not done here — it is the venv package's responsibility for per-engine venvs. Main venv only gets torch via `env.CreateMain`.

## What C5.5 / C7.3 needs to know

- `launcher.NewWithOptions` is the extension point for env mode.
- The conda path is still the default; nothing changes for existing installs.
