# C7.2 — Blue/green engine updates

**Date**: 2026-10-29  
**Branch**: core/wave-7  
**Commit**: b0cd80f

## What now exists

**Package `core/internal/engine/update`**
- `UpdateVenv(ctx, root, m, gpuLabel)` — installs new timestamped venv, smoke-tests python binary, atomically swaps pointer file, GCs old venvs (>7 days).
- `UpdateNative(ctx, m, gpuLabel, cacheDir, mgr)` — resolves new binary via `native.Resolve`, stops/restarts engine via `*lifecycle.Manager`, updates registered manifest, GCs old cached version dirs.
- `GarbageCollect(root, name, keepDays)` — removes `<name>@<version>` dirs older than keepDays except the current pointer.

**`core/internal/engine/venv`** additions
- `BuildVenv(ctx, root, m, gpuLabel, version)` — creates venv at explicit version, no pointer write.
- `SanitizeName(packageName)` — exported wrapper for sanitizeName.
- `install` refactored to call `buildVenv` + write pointer.

**`core/internal/engine/lifecycle`** additions
- `UpdateManifest(id, man)` — replaces registered manifest for stopped engine.
- `Manifest(id)` — returns registered manifest.

**CLI**: `tts-webui engine update <id> [--root <dir>]` (venv and native kinds).

## Decisions

- New version tag for venv blue/green: UTC timestamp `20060102T150405`. No manifest version field yet; each update installs a fresh timestamped dir.
- Native update uses manifest-pointer swap in the lifecycle manager (no file rename). `mgr=nil` in CLI mode → resolve+GC only, no stop/restart.
- Health check: `python -c "import sys; sys.exit(0)"` with 30 s timeout. Verifies Python binary is executable; package-level import check deferred until manifest schema has a `smoke_import` field.

## Tests

Unit tests: pointer-file swap, health failure cleanup, GC (old removed, current kept, empty dir). `TestUpdateManifest_SwapsManifest` covers the new lifecycle methods. All behind fake dirs, no uv or real processes.
Integration tests: tag `integration` (not written; real uv/binary needed).

## Known issues / deviations

- Venv version comes from timestamp, not from a manifest semver field — no manifest version field exists yet. C7.3 may add one.
- `UpdateNative` rollback only restores the old manifest pointer; it does not physically restore the old binary bytes (they stay in the versioned cache dir, unmodified).

## What C7.3 needs to know

- `venv.BuildVenv` and `venv.SanitizeName` are now public; no symbol clashes expected.
- `lifecycle.Manager.UpdateManifest` and `Manifest` are new public methods.
- The `update` package is ready for use by any future component that needs to trigger an in-process engine update without a CLI roundtrip.
